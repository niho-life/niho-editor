## 要望（オーナー 2026-11-05）

1. 指示すると、AI の途中の思考が流れて見える（Cursor の Composer）。
2. 推敲は**直接反映（確定）**が基本。「差分を見る」を押したときだけ、どこを消してどう足したかが見える。採用・却下のボタンは置かない。
3. AI が直した所は灰色で出る。
4. 各章の書き出し 1 文（要点）を 5 行だけ書いたら、AI が前後を肉付けする。
5. チャットは Claude のチャットと同じ感じ（普通に AI と会話しているだけ）。思考を白い枠で囲まない。差分の一覧（「1 戻ります。待ち」…）も出さない。NIHO アプリの記事制作ページの UI/UX を参考にする。

NIHO アプリの記事制作 workbench は、求める形を既に実装している（参考にする実物）:

- AI の変更は**即反映して新しい版を保存**。採用の段階は無い（`use-article-authoring-workbench.tsx`）。
- 各ターンの終わりにチャットへ「**版N を保存しました**」「記事本文（案）・+123字」と、文字リンクの「**変更を見る**」「**元に戻す**」（`article-agent-chat-rail.tsx:379-427`）。元に戻すは最後の版だけ。戻したあとに人が編集していたら確認「AIの変更の後に編集された文書があります」。
- 「変更を見る」は**本文側の inline 差分**へ飛ぶ。帯「AIの変更（版N）を表示中」と「プレビューを閉じる」（`artifact-workspace-card.tsx:841-863`、`article-wysiwyg-diff.ts`。足した語＝緑地＋下線、消した語＝赤の取り消し線）。hunk ごとの ✓/✕ はコードにあるが未使用。
- チャット: 人は右寄りの吹き出し（`#E9F4DB`、右上だけ角 4px）、AI は**枠なしの地の文**。思考は脈打つ点と「考えています」＋左罫線の流れる文で、終わると `<details>` の「N秒考えました」に畳む。道具の呼び出しは 1 行ずつ（spinner → ✓/✕）。作業中は「作業しています・0:12」。ターンが終わると工程は「作業 N件・M秒 ›」の 1 行に畳む（`chat-rail.tsx:288-377, 532-540`）。
- 入力欄: 丸い白い箱、「＋」で「工程を実行」「スキル」（`/` でも開く）、選択は「選択範囲 N 文字」のチップ、送信は ⌘↵、**実行中は送信ボタンが四角の停止**になる。

結論: **4 つとも作れる。** 今の editor は「直接書き換え＋版＋元に戻す」まで持っている。足りないのは、(a) 書き換えを**流しながら本文に入れる**こと、(b) 「変更を見る」の inline 差分、(c) 灰色の mark、(d) 思考・工程の表示（サーバー経路の SSE）、(e) 肉付けの preset。

## 設計

### A. チャットの形（Claude・NIHO アプリと同じ）

- 人の発言は右寄りの吹き出し。選んだ範囲・渡した出典・`/推敲` のようなスキルはチップで吹き出しの中に出る。
- AI の発言は枠なしの地の文。**カード・白い枠・一覧は置かない。**
- **思考の中継は、AI の言葉としてそのまま会話に流す**（オーナー決定 2026-11-05。「N 秒考えました」に畳むのは不可）。例: 「今回のインタビューは本人の生い立ちが重要そうなので、それを中心に記事を組んでみます」。返答と同じ地の文で、消さない・畳まない。モデルには思考を「読者に話しかける一人称の短い段落」で出させる（`thinking` の要約ではなく、`TextDelta` の地の文として設計する。§D）。
- 作業中は、思考の段落の下に薄い 1 行だけ: 「本文を読んでいます…」「直しています 3/5…」「第 2 章を書いています…」（spinner 付き）。終わると消える。
- 終わると残るのは、思考の段落・返答・**版の行**。
- 版の行: 「版 5 を保存しました · −18 字」＋文字リンク「変更を見る」「元に戻す」。元に戻すは最後の版だけ。戻すと「元に戻しました」に変わる。
- 入力欄: 「＋」で工程・スキル（推敲／肉付け／事実確認）、@ で出典、送信ボタンは実行中に四角の停止に変わる。ヘッダーに作業中の表示は置かない。

### B. 直接反映と「変更を見る」

- AI の出力は既存の `edits` / `inserts` の形（段落 index ごと）。streaming では NDJSON（1 行 1 op）で返させ、**届いた op からその場で本文に反映する**（採用の段階は無い）。足す語は灰色で流れ込み、消す語はその場で消える。
- 反映の前に版を切る（既存）。終わったら保存（`baseRevision` 付き。既存の競合処理）。**書いている間は本文を読み取りにする**（人の入力と op の衝突を避ける。「止める」で戻る）。止めたときは届いた分までを保存し「途中で止めました（3/5）」。
- 「変更を見る」: その版の前後を語差分（`diffWords`）にして本文に inline で出す。消した語＝取り消し線の薄灰、足した語＝薄緑の下地＋緑の下線、足したブロック＝左に緑の印と薄緑の下地。本文の上に帯「AI の変更（版 5）を表示中 · 閉じる」、表示中は読み取り専用。チャットの文字リンクは「変更を閉じる」に変わる。差分は ProseMirror の decoration で描き、本文は変えない。
- 「元に戻す」: 版から戻す（既存）。戻したあとに人が編集していたら確認（NIHO アプリと同じ文言）。
- 提案 API（部分採用）はチャットでは呼ばない。`ShellProposal`（上の帯）は退役。

### C. 灰色（AI が書いた印）

- mark `ai` を追加（`page-extensions`、`MARK_NAMES`、`markdown.ts` と公開の描画・翻訳・Google Docs 書き出しでは無視）。AI が足した語・肉付けの文は `ai` 付きで本文に入る。
- 人が打った文字から `ai` を外す plugin（`appendTransaction` で挿入範囲の `ai` を剥がす。`inclusive: false`）→ **書き換えた分だけ黒に戻る**。
- CLI 経路は Markdown 往復で mark が落ちるので、書き戻しで before／after を `diffWords` し、足した語に `ai` を付け直す。
- ⋯ メニューに「AI の文を灰色で見せる」（既定 ON）。色だけに頼らない: 灰色の文は hover で「AI が書いた」。色は `--ed-ink-mute`（本文 16px で AA）。

### D. 思考の中継

- サーバー経路の `POST /api/pages/:id/ai/chat/turns` を **SSE** にし、Anthropic は `stream: true`。tool_use の合間にモデルが出す地の文（今の `items` の `narration`）を `TextDelta` として流し、画面はそれを**そのまま AI の発言として**出す。tool_use → `ToolUse` / `ToolResult`（作業中の薄い 1 行の元）、最後に `Done`。**イベントの形は CLI 経路の `ShellAiEvent` と同じ**にし、画面は 1 本の描画で済ませる（CLI 経路は今の 1 行化をやめてそのまま通す）。
- モデルの `thinking`（内部の推論）は画面に出さない。代わりに system で「作業の前と途中で、何を読んで何をどう直すつもりかを、読者に話しかける短い段落で書いてから道具を使う」と指示する（Cursor の Composer・Claude Code が道具の合間に出す文と同じ）。CLI 経路（Claude Code 等）はもともとこの形で出す。
- 中継した文は会話の `items`（narration）として残す（今と同じ）。token は output として `ai_usage` に数える。ログには出さない。
- Cloud Run は streaming 応答可。timeout は既存の 120 秒のまま。

### E. 肉付け（書き出し → 前後を埋める）

- preset `expand`（mode: `insert`）。各段落を「章の書き出し」として扱い、`inserts` で前（見出し案）と後（1〜3 段落）を足す。`edits` は既存の insert モードが捨てる → **人の行は一字も変わらない**。
- 資料は参照（@ で渡した録音の文字起こし・参照ページ）だけ。資料に無い事実は書かず `〔要確認: …〕` を置く。文字起こし由来の段落には時刻の出典（録音ブロックの時刻へのリンク）。
- 録音の「記事にする」手順（§7.2）とは別。手順は資料から**文書を作る**、肉付けは**人の骨組み**に肉を足す。

## 実現性の目安

| 部品 | 作業 | 大きさ |
| --- | --- | --- |
| 流しながら反映 | op ごとの `replaceBlocks` 相当（段落単位の transaction）、読み取り専用の切替、止める | 中 |
| 変更を見る | 版の前後の語差分 → decoration、帯、読み取り専用 | 小〜中（差分の計算は既存） |
| 灰色の mark | mark＋plugin＋検証の whitelist＋markdown／公開／翻訳／書き出しで無視 | 小〜中（触る場所が散る） |
| 思考・工程 | `anthropic.ts` の stream、`chat-api` の SSE、`ai-client` の reader、チャットの描画。CLI 経路はイベントを通すだけ | 中 |
| 肉付け | preset＋prompt＋出典＋〔要確認〕 | 小 |

段階: (1) チャットの形＋版の行＋変更を見る（非 streaming でも成立）→ (2) 灰色 → (3) SSE と思考・工程 → (4) 流しながら反映 → (5) 肉付け。

## リスク・決めること

- 書いている間に本文を読み取りにする時間が長いと窮屈。op 単位で反映するので、長くても数十秒。「止める」を常に出す。
- 中継の文は途中の考えで、結論（返答）と食い違うことがある。文体を一人称の「〜してみます」「〜にします」にそろえ、結論は最後の返答で言い切る。
- `ai` mark を落とし忘れる経路（公開 API・翻訳・Google Docs・Markdown）は schema テストに `ai` を足した時点で全部直す。
- IME の変換中の文字に `ai` を付けない（composition の transaction で剥がす）。
