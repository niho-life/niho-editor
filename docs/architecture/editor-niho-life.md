# editor.niho.life：ページを書く工房

2026-10-30 のオーナー判断。NIHO docs（このリポジトリ）が担ってきた機能を、`editor.niho.life` という一つの Web の書斎に統合する方針。このリポジトリは `niho-editor` に改名し、`editor.niho.life` を担当範囲とする。`docs.niho.life` は作らない。

現行モックは [`docs/mockups/editor-niho-life-v7.html`](../mockups/editor-niho-life-v7.html)（HTML 1 枚、画像とフォントを内蔵）。v6 は履歴として保持し、v7 は書式・AI 設定・30 MiB 上限・Web/Mac の AI 経路を反映した canonical source。開いたら上の黒い帯の「地図」から全画面へ飛べる。

## 位置づけ

- NIHO は、街の人が複数の役割（ライター、体験ホスト、リビングのオーナー、住民）を持ち、手をつなげるようにする土台。アカウントは NIHO アカウント一つで、どの画面にも同じアカウントで入る。
- `editor.niho.life`（製品名 NIHO editor）は、いろいろな文書をどんどん作り出すための工房・書斎。近いのは Notion や note。思考メモ・会議の録音・旅行者向けの記事・住民向けの手引きが、同じ場所に同じ操作で並ぶ。
- 書いたものを公開するかどうかは本人が決める。公開するとき、記事本体の正式な URL をどこに置くか（発信先）を毎回選ぶ。note と違い、書く場所と公開する場所を分ける。

## 原則

1. **まずページを書く。** 空のページに書き始めるのが中心で、ほかは全部あとから足せる。
2. **既定は「自分だけ」。** すべてのページを公開するとは限らない。思考メモは公開しないまま残る。
3. **AI・文字起こし・公開は、ページの上に薄く載る。** 必要なときだけ出てくる。説明文を画面に置かない。
4. **公開は「発信先を選ぶ」ことで、それ以上ではない。** 発信先が記事本体の正式な URL になる。検索エンジンが評価するのはその URL であり、書いた場所（editor）ではない。editor 自体は検索に出さない（noindex）。
5. **同じ言語版を検索に出す発信先は一つ。** NIHO アプリなどほかの面には本文を複製せず、発信先へのリンクを持つカードを出す。
6. **公開版は不変のスナップショット。** 公開後に直した内容は「更新を公開」するまで読者に出ない。公開後の URL は固定し、発信先を移すときは NIHO が運営する面なら旧 URL から転送する。
7. **本人のサイトにも同じ仕組みで出せる。** NIHO の面も本人のサイトも、同じ公開 API（JSON と Markdown）を読む。WordPress などへの送信は使う人が見えてから足す。書き出し（Markdown と写真）はいつでもできる。
8. **メタファーを使わない。** 家・窓・出荷・原稿といった言葉は使わず、画面の言葉はそのまま意味が分かるものにする（下の用語）。

## 画面の構成

| 場所 | 内容 |
| --- | --- |
| 左のサイドバー | 「新しいページ」（空のページ／録音から／音声ファイルから）、検索、すべて／公開中／録音の絞り込み、ページの一覧。一覧は更新順で、日付のグループは出さない。録音から作ったページは録音の下に少し下げて並ぶ。下に「発信先」「役割とつながり」「設定」と本人 |
| ページ | 題名、本文。書式のバーに AI の入口。任意のカバー写真・リードは右のページ設定で編集し、未設定でも公開できる。右上に状態（自分だけ／公開中／限定公開／更新あり／公開をやめた）と「公開」、情報パネル、「…」（リンクで共有、書き出し、履歴、複製、削除） |
| 情報パネル | 公開の状態と発信先、公開の前に直すこと、カテゴリ、関連する体験（NIHO Experience のとき）、言語、著者、作成・更新、書き出し |
| 公開のシート | 発信先（NIHO Experience／NIHO／自分のサイト／発信先を追加）、範囲（公開／限定公開）、あわせて（NIHO アプリに載せる、ニュースレター、体験ページに載せる）、公開の前に直すこと、URL |
| 設定 | 発信先の接続（公開 API の URL と鍵、WordPress、書き出し）、役割とつながり（NIHO アカウント、役割、記事連携）、プロフィール、AI、文字起こし、手順、保存先 |

発信先ごとに公開の条件が違う。NIHO Experience は英語・カテゴリ・未確認の印（CONFIRM）の解消、NIHO はカテゴリ、自分のサイトは条件なし。条件は発信先を選んだ瞬間にその発信先のものに変わり、足りないものは「直す」でその欄へ戻れる。カバー写真とリードは任意で、未設定でも公開できる。

## 文字起こしと手順

録音のページには、音声と話者つきの文字起こしがある。AI で「記事にする」を選ぶと、手順（NIHO docs の工程設計にあたる）が始まり、録音のページの下にサブページができる。

```
録音のページ（文字起こし）
  ├ 文字起こし修正
  ├ 記事方針
  └ 記事本文   ← ふつうの記事のページ。ここから公開できる
```

- 各ページの上部に手順の帯（文字起こし › 文字起こし修正 › 記事方針 › 記事本文）が出て、今の位置と済んだものが分かり、帯から行き来できる。
- サブページはふつうのページなので、そのまま手で直せる。直した内容は次の手順に使われ、「作り直す」でその手順だけやり直せる。
- 手順の並びはテンプレート（記事制作、議事録、インサイト整理）として設定に置き、編集・追加できる。
- 録音は、手順を使わずにページとして残すだけでもよい。

## 公開と検索

- 発信先の例：`experience.niho.life/guides/{slug}`（旅行者向け・英語）、`niho.life/article/{slug}`（鎌倉の人向け）、本人のサイト。市民向けの記事は NIHO Experience には載せない。発信先は記事ごとに違ってよい。
- 発信先の面が editor の公開 API から公開版を受け取り、自分のドメイン・自分のデザイン・自分の canonical で描画する。本文は構造（限定 AST）で渡し、HTML で渡さない。
- NIHO アプリは発信先の一つではなく「あわせて載せる」面。カードで案内し、本文を持たない。アプリ内の検索はアプリの中で完結する。
- 日本語版・英語版は同じページの言語版として editor が持ち、発信先が言語版を選ぶ。

## 役割と権限

- 役割（ライター、鎌倉の人、住民、体験ホスト）は NIHO アカウントに付く。editor は役割を見て「出せる発信先」を並べるだけで、権限の判断はしない。発信先の面は公開版を受け取るときに自分の条件（体験が掲載中か、など）を再確認する。
- 体験ホストがライターを記事連携に招待し、ライターが受けると、そのホストの公開中の体験を記事に関連付けられる。この招待・承諾・取消の正本は NIHO 側の役割の層に置き、experience の中に閉じない。
- ログインは NIHO アカウント。NIHO アプリ、ホストの画面、公開サイトのどこからでも同じ editor に着く。

## 既存との関係と移行

| 今あるもの | これから |
| --- | --- |
| NIHO docs の Mac アプリと Web（録音、文字起こし、工程設計、AI と作る、Google ドキュメント書き出し、リンクで共有） | 機能は editor.niho.life に取り込む。工程設計は「手順」、成果物はサブページ、AI と作るはページの AI として残る。リポジトリは `niho-editor` に改名。Mac アプリは同じ方針で作り直して存続（端末内の文字起こしと「この Mac だけ」の保存は Mac だけ） |
| niho-experience の `/editor`（下書き、版、写真と許諾、公開前の検査、TipTap の本文） | editor.niho.life へ移す。experience は発信先に専念し、`/guides` の公開描画（SSR、JSON-LD、sitemap、hreflang）と記事⇄体験の相互リンク、体験の掲載状態の検証を残す |
| 記事の正本は niho-experience（ADR 0002） | 記事の正本は editor。experience は公開 API から読む。ADR を更新する |
| experience の記事連携（招待・承諾・取消） | NIHO アカウントの役割の層へ移す |
| NIHO アプリ | 役割のハブ。アカウント設定の「書く」（体験への導線と並ぶ）から editor へ。公開した記事はカードで載る。editor 用の接続（`niho-experience-editor` クライアント）は editor.niho.life の接続として使う。`niho.life/article` は editor の公開 API を読む新しい面 |

進め方は、experience の公開面を今の設計のまま進めつつ、読み取り元を自分の DB から editor の公開 API に差し替えられる形にしておき、editor ができたら `/editor` を移す。NIHO docs の機能は Web の editor に一つずつ移し、Mac アプリは同じ部品で同じ方針に作り直す。

## 決めたこと（2026-10-30）

- 製品名は **NIHO editor**。ドメインは `editor.niho.life`、リポジトリは `niho-editor`。
- Mac アプリは残す。既存の NIHO docs の Mac アプリを、この方針（ページ中心・発信先・手順）に作り直して存続させる。Web と同じ `docs-core`／`docs-ui` を使う。
- `niho.life/article` は、editor の公開 API を読む新しい面として作る。kamakura CMS（Kamakura-site のサイト CMS）は使わない。
- 公開サイト（niho-experience）のフッターの「For writers」は残し、`editor.niho.life` へ飛ばす。
- NIHO アプリの「書く」は、アカウント設定の中に置く。同じ場所にある体験（ホスト）への導線と並べる。

- 日本語で書いて英語版を作る流れ（niho-experience #213）の扱い。

## 用語

| 使う | 意味 |
| --- | --- |
| ページ | 書くものの単位。画面にはあまり出さない |
| 自分だけ | 公開していない状態（既定） |
| 公開／限定公開／更新あり／公開をやめる | 公開の状態と操作 |
| 発信先 | 記事本体の正式な URL になる場所 |
| あわせて | 発信先に加えて載せる面（NIHO アプリ、ニュースレター、体験ページ） |
| 録音／文字起こし／話者 | 音声まわり |
| 手順 | 文字起こしから記事などを作る工程の並び |
| 役割とつながり | NIHO アカウントの役割と記事連携 |

使わない言葉：家、窓、出荷、原稿、工房（画面の中では）。

## モックの前提

- 人物・ページ・体験は仮。ボタンは見た目だけで、保存や公開はしない。
- 写真は niho-experience の `apps/web/public/sample/photos` と同じ仮素材（Unsplash License の写真と、NIHO kamakura の自前の写真。出典は同リポジトリの `CREDITS.md`）。製品の写真ではない。
