# editor.niho.life：ページを書く工房

2026-11-07更新（#332）：Experienceの記事はExperienceの `/write` で書き、正本をExperience DBに置く。editorからExperienceへの公開・公開API読取・プレビュー・記事連携を凍結する。editorは個人ページと接続済みの本人サイトへの公開を維持し、保存済みのページ・公開版・履歴は削除しない。旧 `exp` / `niho` 識別子は保存データの互換のためにだけ残し、公開能力や画面の選択肢には使わない。

2026-10-30 のオーナー判断。NIHO docs（このリポジトリ）が担ってきた機能を、`editor.niho.life` という一つの Web の書斎に統合する方針。このリポジトリは `niho-editor` に改名し、`editor.niho.life` を担当範囲とする。`docs.niho.life` は作らない。

現行モックは [`docs/mockups/editor-niho-life-v7.html`](../mockups/editor-niho-life-v7.html)（HTML 1 枚、画像とフォントを内蔵）。v6 は履歴として保持し、v7 は書式・AI 設定・30 MiB 上限・Web/Mac の AI 経路を反映した canonical source。開いたら上の黒い帯の「地図」から全画面へ飛べる。

## 位置づけ

- NIHO は、街の人が複数の役割（ライター、体験ホスト、リビングのオーナー、住民）を持ち、手をつなげるようにする土台。アカウントは NIHO アカウント一つで、どの画面にも同じアカウントで入る。
- `editor.niho.life`（製品名 NIHO editor）は、いろいろな文書をどんどん作り出すための工房・書斎。近いのは Notion や note。思考メモ・会議の録音・旅行者向けの記事・住民向けの手引きが、同じ場所に同じ操作で並ぶ。
- 書いたものを公開するかどうかは本人が決める。公開するとき、記事本体の正式な URL をどこに置くか（発信先）を毎回選ぶ。note と違い、書く場所と公開する場所を分ける。

## 原則

1. **まずページを書く。** 空のページに書き始めるのが中心で、ほかは全部あとから足せる。
2. **既定は「自分だけ」。** すべてのページを公開するとは限らない。思考メモは公開しないまま残る。
3. **AI・文字起こし・公開は、ページの上に薄く載る。** 必要なときだけ出てくる。説明文を画面に置かない。
4. **公開は「発信先を選ぶ」ことで、それ以上ではない。** 発信先が記事本体の正式な URL になる。検索エンジンが評価するのはその URL であり、書いた場所（editor）ではない。editor 自体は検索に出さない（noindex）。
5. **同じ言語版を検索に出す発信先は一つ。** NIHO アプリなどほかの面には本文を複製せず、発信先へのリンクを持つカードを出す。
6. **公開版は不変のスナップショット。** 公開後に直した内容は「更新を公開」するまで読者に出ない。公開後の URL は固定し、公開停止や URL 移行時の転送は発信先の契約に従う。
7. **本人のサイトにも同じ仕組みで出せる。** 接続済みの本人のサイトが公開 API（JSON と Markdown）を読む。WordPress などへの送信は使う人が見えてから足す。書き出し（Markdown と写真）はいつでもできる。
8. **メタファーを使わない。** 家・窓・出荷・原稿といった言葉は使わず、画面の言葉はそのまま意味が分かるものにする（下の用語）。

## 画面の構成

| 場所 | 内容 |
| --- | --- |
| 左のサイドバー | 「新しいページ」（空のページ／録音から／音声ファイルから）、検索、すべて／公開中／録音の絞り込み、ページの一覧。一覧は更新順で、日付のグループは出さない。録音から作ったページは録音の下に少し下げて並ぶ。下に「設定」。発信先と本人情報は設定から開く |
| ページ | 題名、本文。書式のバーに AI の入口。任意のカバー写真・リードは右のページ設定で編集し、未設定でも公開できる。右上に状態（自分だけ／公開中／限定公開／更新あり／公開をやめた）と「公開」、情報パネル、「…」（リンクで共有、書き出し、履歴、複製、削除） |
| 情報パネル | AIと作る。記事の情報と公開の条件は公開シート、作成・更新と文字数はページ情報に置く |
| 公開のシート | 発信先（接続済みの自分のサイト／発信先を追加）、記事の情報、公開の前に直すこと、URL |
| 設定 | 発信先の接続（公開 API の URL と鍵、WordPress、書き出し）、役割とつながり（NIHO アカウントの本人情報。Experienceの記事連携は表示・操作しない）、プロフィール、AI、文字起こし、手順、保存先 |

発信先ごとに公開の条件が違う。現在の発信先は本人のサイトで、接続先の条件に従う。条件は発信先を選んだ瞬間にその発信先のものに変わり、足りないものは「直す」でその欄へ戻れる。カバー写真とリードは任意で、未設定でも公開できる。

## 文字起こしと手順

録音のページには、音声と話者つきの文字起こしがある。AI で「記事にする」を選ぶと、手順（NIHO docs の工程設計にあたる）が始まり、録音のページの下にサブページができる。

```
録音のページ（文字起こし）
  ├ 文字起こし修正
  ├ 記事方針
  └ 記事本文   ← ふつうの記事のページ。ここから公開できる
```

- 各ページの上部に手順の帯（文字起こし › 文字起こし修正 › 記事方針 › 記事本文）が出て、今の位置と済んだものが分かり、帯から行き来できる。
- サブページはふつうのページなので、そのまま手で直せる。直した内容は次の手順に使われ、「作り直す」でその手順だけやり直せる。
- 手順の並びはテンプレート（記事制作、議事録、インサイト整理）として設定に置き、編集・追加できる。
- 録音は、手順を使わずにページとして残すだけでもよい。

## 公開と検索

- editorからの発信先は接続済みの本人のサイト。公開APIから不変の公開版を受け取り、自分のデザインとcanonicalで描画する。本文は構造（限定AST）とMarkdownで渡す。
- Experience記事はExperienceの `/write` で書き、Experience DBを正本として公開する。editorのページから公開・プレビュー・記事連携を行わない。NIHOアプリへのカードもExperience側の責務。
- 将来editorへ全面移管する場合は別途判断する。今回の凍結では保存済みのページ・公開版・履歴を削除しない。

## 役割と権限

- NIHOアカウントでログインし、editorの個人ページを使う。本人サイトへの公開には本人の解除していない接続を使う。
- editorはExperienceのwriter許可、関連体験・カテゴリ、記事招待を読み取らず、承諾・辞退も行わない。Experienceの記事連携操作はExperience側の `/write` で扱う。
- NIHO本人認証の接続は維持する。互換のclient IDにExperienceという名前が残っていても、記事公開を許可する根拠にはしない。

## 既存との関係と移行

| 今あるもの | 現在の方針 |
| --- | --- |
| NIHO docs の Mac アプリと Web（録音、文字起こし、工程設計、AI、Google ドキュメント書き出し、リンクで共有） | Webのeditorへ統合し、Macは同じUIを読む殻として存続 |
| Experienceの記事編集・公開 | Experienceの `/write` とDBを使う。editorへの移管計画は凍結 |
| Experienceの記事連携（招待・承諾・取消） | Experience側で扱い、editorの表示・操作と上流呼び出しを閉じる |
| editorの本人サイト接続 | 公開・プレビュー・書き出しを維持 |
| editorの旧Experience公開版 | 保存を維持するが、旧資格・token・設定でも公開APIから読めず、新規公開先にも選べない |

NIHO docsの機能はWebのeditorへ移し、Macは同じ部品を使う。Experienceの正本をeditorへ移す作業は進めない（Experience #476、editor #332）。

## 決めたこと（2026-10-30）

- 製品名は **NIHO editor**。ドメインは `editor.niho.life`、リポジトリは `niho-editor`。
- Mac アプリは残す。既存の NIHO docs の Mac アプリを、この方針（ページ中心・発信先・手順）に作り直して存続させる。Web と同じ `docs-core`／`docs-ui` を使う。
- 旧決定の `niho.life/article` 新設は2026-11-03に撤廃した。Kamakura-site CMSへ置き換える作業も行わない。
- Experienceの「For writers」と記事作成導線はExperienceの `/write` へ向ける（2026-11-07に変更）。
- NIHO アプリの「書く」は、アカウント設定の中に置く。同じ場所にある体験（ホスト）への導線と並べる。

## 決めること

- 将来Experienceの執筆をeditorへ全面移管するかは、必要になった時点で別途決める。

## 用語

| 使う | 意味 |
| --- | --- |
| ページ | 書くものの単位。画面にはあまり出さない |
| 自分だけ | 公開していない状態（既定） |
| 公開／限定公開／更新あり／公開をやめる | 公開の状態と操作 |
| 発信先 | 記事本体の正式な URL になる場所 |
| あわせて | 発信先に加えて載せる面（NIHO アプリの記事カードなど）。本文の公開先を増やさない |
| 録音／文字起こし／話者 | 音声まわり |
| 手順 | 文字起こしから記事などを作る工程の並び |
| 役割とつながり | NIHO アカウントの役割と記事連携 |

使わない言葉：家、窓、出荷、原稿、工房（画面の中では）。

## モックの前提

- 人物・ページ・体験は仮。ボタンは見た目だけで、保存や公開はしない。
- 写真は niho-experience の `apps/web/public/sample/photos` と同じ仮素材（Unsplash License の写真と、NIHO kamakura の自前の写真。出典は同リポジトリの `CREDITS.md`）。製品の写真ではない。
