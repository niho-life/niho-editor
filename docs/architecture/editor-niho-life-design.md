# editor.niho.life：詳細設計

2026-11-03更新：運営する記事公開先はExperienceに絞る。「鎌倉の人」の役割と `niho.life/article` は撤廃し、NIHO Adminで承認された現在writerだけがExperienceへ公開できる。住民/ホスト/住所から公開許可を推測しない。個人ページの作成と既存の本人サイト接続は維持する。旧wire識別子が互換のため残っても、新規公開を許可する能力・画面の選択肢には使わない。NIHOアプリのカードはExperience記事への導線で、別の本文公開面ではない。

[editor-niho-life.md](editor-niho-life.md)（方針）を画面と契約に落としたもの。Epic は niho-editor [#30](https://github.com/niho-life/niho-editor/issues/30)、niho-experience [#251](https://github.com/niho-life/niho-experience/issues/251)、niho-app [#19477](https://github.com/niho-coliving/niho-app/issues/19477)（役割・接続・カード）。子 Issue は各 Epic の一覧にある。

## 1. 使う人と場面

| 人 | 場面 | 設計で守ること |
| --- | --- | --- |
| 考える人 | 長いメモ。あとで AI に整えてもらい、記事にするかもしれない | AI は呼んだときだけ。変更は差分で見て選べる。元に戻せる |
| 録音から作る人 | ホストとの会話、会議。文字起こしから記事や議事録を作る | 録音と文字起こしはページの一部。手順の進み具合が常に見える。各段階を手で直せる |
| ライター | 旅行者向けの英語記事。写真の許諾や関連する体験など条件が多い | 条件は発信先を選んだ瞬間に出る。足りないものから直せる。公開後に何が起きるかが一言で分かる |
| ホスト | 自分の体験の話を書く。ライターに書いてもらう | ホストの画面から同じアカウントで入れる。記事連携の招待と取消が分かる |
| 個人で書く人 | 自分だけのページや個人サイトの記事を書く | NIHOの公開権限がなくてもページを作り、本人サイトへ接続できる |

原則：最小の入口（新しいページ一つ）、既定で安全（自分だけ）、可逆（版・履歴・公開をやめる）、状態が常に見える（右上の状態、保存の表示、手順の帯）、説明より構造、キーボードと IME を壊さない、スマホでは読む・少し直す・公開を止めるができれば十分。

## 2. 情報設計と URL

| URL | 画面 |
| --- | --- |
| `/` | サイドバー＋最後に開いたページ（なければ新しいページ） |
| `/p/{id}` | ページ |
| `/p/new` | 新しいページ（開いた時点で空でも下書きを作り、`/p/{id}` になる。公開ボタンと情報パネルは入力前から使える） |
| `/p/{id}/preview?to={dest}` | 発信先での見え方（発信先が発行するプレビュー URL を埋め込む） |
| `/destinations`、`/destinations/{id}` | 発信先の一覧と、本人のサイトの接続 |
| `/account` | 役割とつながり |
| `/settings`、`/settings/about`、`/settings/terms`、`/settings/recipes/{id}` | 設定の一覧（AI・手順・データ）と、あなたについて・固有名詞・手順の詳細（§2.2） |
| `/auth/login`、`/auth/callback`、`/editor/auth/callback` | Google/PhotoとNIHO Experience editorを分けたアカウント接続 |
| `/s/{token}` | リンクで共有（読み取り専用、ログイン不要） |

### 2.1 保存先（正本はサーバーだけ）

正本は **NIHO クラウド（サーバー）だけ**。ページ・録音・版・資産はすべてサーバーにあり、Mac アプリ・ブラウザ・PWA は**同じものを読み書きする**。アカウントや端末ごとに保存先を選ぶ仕組みは持たない（オーナー決定 2026-11-01。Issue #50 はこの線に縮める）。

- **「この Mac だけ」は保存先ではない。** Mac にあるのは**端末内の文字起こしのための一時置き場**だけ。文字起こしする音声（と参照する本文）をその間だけ Mac に置き、終わったら**結果をサーバーの録音に書いて**一時置き場を消す（§7.1・§13）。Mac だけのページの一覧や、サーバーに上げないページは持たない。
- **オフライン**は §12 の「オフライン・この端末に保持」（復帰したら保存する一時保持）だけ。オフラインを主な作業場にすることはしない。
- **以前の案は採らない**：`DocsStorageMode` の `LOCAL`／`CLOSING`、クラウド ↔ この Mac の切り替え、`desktop-vault` の三方向併合。旧 NIHO docs のその仕組みは、Mac アプリの殻への置き換え（§13）とともに退役させる。旧版のデータは editor に移さず、この切り替えでは既存の `~/Documents/NIHO docs` を自動削除しない。旧 Web の停止日と旧 URL の扱いは [editor-migration-map.md](editor-migration-map.md) §4 で決める。
- **容量の表示**：設定の一覧の「データ › メディア容量」（内訳と数えるものは ⓘ の中）に、アップロード済みページ画像と保持期限内の録音音声の容量・内訳を出す（Issue #50）。ゴミ箱内も完全削除まで含める。ページ本文・版履歴はDB保存のため対象外、NIHO Photoライブラリは独立した容量管理のため対象外。アカウントの容量上限は未設定とし、保存を容量で拒否しない（オーナー決定 2026-11-01）。

`editor.niho.life` は全ページ `noindex, nofollow`。公開 API は `api.editor.niho.life`（§9）。入口は、NIHO アプリのアカウント設定の「書く」（体験への導線と並ぶ）、niho-experience のホストの画面と公開サイトのフッター「For writers」、そしてブックマーク。製品名は NIHO editor。

### 2.2 設定（3 層。オーナー決定 2026-11-05）

モックは [`docs/mockups/editor-settings-refine-v1.html`](../mockups/editor-settings-refine-v1.html)。人は「何かを変えたくて」設定を開くので、変えられる物だけを並べ、深い物は奥へ置く。

- **3 層**：一覧（`/settings`）→ 詳細ページ（`/settings/about`・`/settings/terms`・`/settings/recipes/{id}`）→ 集中編集のシート（段階の指示・文書ガイドのような長文。デスクトップは右に全高、スマホは全画面）。
- **一覧の先頭は「アカウント」の群**（オーナー決定 2026-11-06。左下の「設定」を直リンクにしたので、メニューにあった物をここへ移す）：本人の名前の行 › 役割とつながり（`/account`。未処理の招待があればバッジ）、発信先 ›（`/destinations`）。いちばん下に薄く「ログアウト」。発信先・役割とつながりのページは「← 設定」で一覧へ戻る（URL は今のまま）。
- **一覧には変えられる物だけ**を行にする：AI（提案の言語・あなたについて・固有名詞）／手順（1 行 1 手順）／データ（AI の使用量・メディア容量）。行そのものが詳細へのリンクで、**「編集」ボタンは置かない**。提案の言語だけは 1 タップで決まるのでその場で保存する。説明は ⓘ の中（押すと行の下に開く）。
- **事実は使う場所へ移す**：受け付ける形式 → ファイル選択の accept と断るときの文。1 ファイルの上限・音声の 30 日 → 一覧の「データ」の ⓘ と録音の断り。文字起こしのエンジン名・時間切れ → 設定には出さない（使う人が決めるものではない）。
- **手順のページは操作ごとにすぐ保存する**（名前・段階の並べ替え／複製／削除・段階と文書ガイドのシートの保存・お手本を外す・固有名詞の 1 行）。ページ全体の「保存」は持たず、結果は見出しの下の 1 行で言う。並べ替えは ⋯ のメニューで行う（ドラッグは作らない）。

## 3. ページのモデル

```
Page
  id, kind: note | rec | article | step
  title, lang: ja | en
  blocks: Block[]            ← 本文の正本（限定 AST）
  cover?: Asset, lead?: string
  recording?: { asset, transcript: Segment[], speakers: Speaker[], engine }
  parent?: PageId, children: PageId[], recipe?: RecipeId, stepStatus?: done | run | wait | stale
  versions: Version[]        ← 自動保存のスナップショットと AI の版
  publication?: { dest, slug, range: live | unlisted, publishedVersion, category?, related?: ExperienceSlug[], extras: { app, news, xp } }
  share?: { token, enabled }
  author: snapshot of profile at publish
  createdAt, updatedAt, deletedAt?
```

Block は段落、見出し（2・3）、箇条書き・チェックリスト（完了状態を保存）・番号付き、表（行・セル・見出しセル）、コードブロック、引用、画像（Asset 参照、alt、クレジット、掲載許諾）、区切り線、録音（Asset 参照）、囲み。行内は太字・斜体・取り消し線・インラインコード・安全なリンク・改行。HTML は保存しない。表はセルごと編集し、行・列を追加・削除できる。狭い画面では表の中だけを横にスクロールする。発信先へは JSON（AST）と、発信先が読める安全な Markdown サブセット（niho-experience の `lib/guide-markdown.ts` が受ける範囲）の両方を出す。

`kind` は見た目と初期値を決めるだけで、あとから変えられる（メモを記事として公開したら `article` になる）。日記という種類は持たない（オーナー判断 2026-10-31。日記のように使うなら、ふつうのメモ）。

## 4. サイドバー

- 「最近」の節は一旦表示しない（オーナー判断 2026-11-03）。ページの木と検索から開く。
- 並びは更新順。日付や月の見出しは出さない。ピン留めは v1 では持たない（必要になったら上に「ピン」節を足す）。
- 録音から作ったサブページは親の下に少し下げて並ぶ。親を開いても閉じても一覧は変わらない（折りたたみは v1 では持たない）。
- 各行：題名（無題は薄く「無題」）、2 行目は公開中なら URL、録音なら「録音」、手順のサブページなら「手順」、それ以外は更新時刻。右端に録音のマークと公開中のマーク。手順が動いているページは回るマーク。
- 絞り込み：すべて／公開中／録音。検索（⌘K）は題名と本文を対象に、打つたびに絞る。
- 一覧の上は 1 行：左にアプリのアイコンと「Editor」、右に「検索」「＋（新しいページ）」「一覧をしまう」のアイコン（言葉は吹き出し。オーナー決定 2026-11-06。2026-11-05 の「2 行にする」を上書き。モック `docs/mockups/editor-shell-refine-v1.html`）。「＋」：空のページ、録音から、フォルダ（オーナー決定 2026-11-06。音声ファイルは録音ページの録音ブロックで取り込む）。開いているページがフォルダの中なら、メニューの上に「『◯◯』の中に」が付き、その中に作る。⌘N は空のページ、⌘K は検索。一覧をしまったときは、ヘッダーの「一覧を出す」の右隣に同じアイコンと「Editor」を出す（900px 以下では出さない）。
- **フォルダは `kind = 'folder'` のただの入れ物**（オーナー決定 2026-11-06。[editor-recipes-and-folders.md](editor-recipes-and-folders.md) §3）。空で作れ、本文も欄も持たず、公開・録音・工程の親にならず、入れ子にしない。一覧では子が無くてもフォルダのアイコンと開閉で出る。開くと中身の一覧と「新しいページ」「録音から」。
- 行をドラッグしてフォルダへ入れる（行の中央へ落とす）・並べ替える（行の上下の縁へ落とす）。キーボードとスマホの代替はヘッダーの「…」の「移動…」（フォルダの選択と上へ・下へ）。右のレールにフォルダ・並びの欄は置かない（オーナー決定 2026-11-05）。行の「…」（右クリック・Shift+F10 でも）は「削除」だけ（確認のあとゴミ箱に 30 日。開いていないページも消せる。フォルダなら中のページの数を言う。オーナー決定 2026-11-06）。
- 一覧の下：「このページの写真」（オーナー決定 2026-11-05。モック `docs/mockups/editor-photo-library-v1.html`）。ページを開いているときだけ出し、既定は写真アイコンの 1 行だけに閉じる。アイコンを押すと開き、もう一度押すと閉じる（開閉は保存しない）。見出しは文字でなく写真アイコンで、枚数は出さない。開いている間は一覧との境目で高さを変えられる。中身と操作は §5.1 の「写真」。
- 下：「設定」の直リンクだけ（押すとすぐ `/settings`。メニューは持たない。オーナー決定 2026-11-06）。発信先・役割とつながり・ログアウトは設定の一覧の中（§2.2）。未処理の招待のバッジは「設定」と、設定の一覧の「役割とつながり」の行に出す。
- スマホ：一覧がはじめの画面。ページを開くと全画面になり、左上で一覧に戻る。

## 5. ページ

### 5.1 書く

- 題名と本文。画像などは上部のエディタバーから挿入する。本文の空の行の「/」と ⌘/ でもブロックの一覧を開ける。本文の左の「＋」と入力中の緑の囲いは表示しない（オーナー判断 2026-11-03）。ブラウザ既定のフォーカスリング（青い囲い）も出さない。上のバーは挿入（＋・画像・録音）だけで、書式（太字、斜体、取り消し線、インラインコード、リンク、見出し、箇条書き）は選んだ文字の上の帯に出す（オーナー決定 2026-11-05）。AI の操作は右サイドバーへまとめ、本文や選択した文字の上に「✨AI」を置かない。空の行のブロック一覧からチェックリスト、番号付き、表、コードブロックも挿入でき、表では行・列を追加・削除できる。
- 自動保存。保存の状態は普段は何も出さない（「保存済み」「保存中」を画面に置かない。オーナー決定 2026-11-05）。失敗したとき（オフライン・この端末に保持／保存に失敗／保存を止めている／ログインが切れた）だけ右上に琥珀の一言。読み上げは右上の状態の丸の live region が持つ。手動の保存ボタンは持たない。⌘S は保存を即時にするだけ。容量の決まり（1 ページ 30 MiB）は本文の上に書かず、右下の文字数 › ⓘ のシートに置く。
- 版：自動保存は一定間隔で版を残す。AI の変更と公開は必ず版を残す。「…」の「履歴」から版を開き、「この版に戻す」ができる。
- 画像：貼り付け・ドロップ・選択。アップロード中はプレースホルダー。alt とクレジットは画像を選ぶと出る小さな欄で、発信先が要求するときだけ「公開の前に」に出る。
- 写真（オーナー決定 2026-11-05）：**写真の原本はそのページの「このページの写真」（§4）にある**。関連する写真をまずパネルへまとめて上げ（パネルの ＋・パネルへのドロップは本文に入れない）、使う写真だけパネルから本文へドラッグする（落とした段落のあいだに入る）。タイルを押すと大きく見る（本文に入れる・alt・クレジット・掲載許諾・パネルから外す）。狭い画面はドラッグの代わりにこの「本文に入れる」。本文の画像ボタン・貼り付け・本文へのドロップは今までどおり本文に入れ、パネルにも出る。タイルは正方形 3 列・新しい順で、本文で使っている写真に ✓。上限は 1 ページ 100 枚（パネルに上げただけの写真も数える）。形式は本文の画像と同じで、HEIC はまだ受けない。
  - パネルから外すと、その写真は本文（全ての出現）とカバーからも消える（確認で箇所数を出す。元に戻せない）。外した写真を使っていた前の版に戻すと、その写真は欠けて出る。公開中の記事は公開時に複製した写真を配信するので変わらない。画像の object は、ゴミ箱の完全削除と同じく資産の行だけを消し、bucket の規則に任せる。
- 新しいページ（§2 の `/p/new`）は開いた時点でできるので、本文を書く前から写真を上げられる。そのタブで作ったページを、題名・本文・写真（ほかの資産・子ページ・公開を含む）のどれも足さずに離れたら、サーバーが空であることを確かめてから消す（ゴミ箱に入れない。オーナー決定 2026-11-05）。
- IME：変換中の入力で保存や書式が走らない。Undo は IME の確定単位。
- 320px〜PC。本文の最大幅は 680px。

### 5.2 記事の要素

カバー写真とリードは任意項目で、本文の上には置かず、「公開」のシートの「記事の情報」（リード・カバー画像・言語・英語版）で編集する（オーナー決定 2026-11-05。右サイドバーの「ページ設定」は廃止）。新規ページは題名と本文から書き始められ、カバー写真・リードを設定しなくても公開・更新できる（オーナー判断 2026-11-03）。リードは 160 文字まで。設定した画像の形式・掲載許諾やリードの長さは引き続き検証する。

### 5.3 状態と上部のボタン

| 状態 | 右上の表示 | ボタン |
| --- | --- | --- |
| 公開していない | 何も出さない（読み上げは「自分だけ」） | 公開（静かな文字ボタン。発信先が決まっているか記事なら主ボタン） |
| 発信先を選んだが未公開 | 「自分だけ」（情報パネルに「〜に公開する予定」） | 公開 |
| 公開中（最新版と一致） | 緑「公開中」 | 公開中 ▾（発信先を変える、公開をやめる） |
| 公開中で本文を直した | 琥珀「更新あり」 | 更新を公開 |
| 限定公開 | 青「限定公開」 | 公開中 ▾ |
| 公開をやめた | 灰「公開をやめた」 | 公開 |

「…」：リンクで共有、書き出し（.md、Google ドキュメント）、履歴、複製、移動…、ページの情報、削除（ゴミ箱に 30 日）。フォルダでは「書き出し（写真つき zip）」「削除」だけ（オーナー決定 2026-11-06。「フォルダの背景…」は録音ページの「この録音について」へ移した）。

ヘッダーの左は場所（親のフォルダ › 親の録音）だけで、ページ名は本文の題名にだけ出す（オーナー決定 2026-11-06）。押すとその場所へ。上の段のページでは何も出ない。スマホはヘッダーに幅が無いので、題名の上の 1 行に出す。

### 5.4 情報パネル

右サイドバーは「AIと作る」だけ（オーナー決定 2026-11-05。2026-11-03 の「上半分をページ設定・下半分を AI」は取り下げ）。サイドバーは既存の背景色を保ち、チャット・吹き出し・入力欄を別の面色で塗り分けない。

- ページの情報（作成・更新・録音・文字数）は本文の列の右下の文字数を押したポップオーバーに出す。容量の決まりはその ⓘ のシートに置く。
- 公開（状態・発信先・足りないもの）・カテゴリ・関連する体験・言語・リード・カバー画像・英語版は公開のシート（§8.1）。
- 書き出し・削除・移動は「…」（§5.3）。登場人物・固有名詞・背景は録音ページの「この録音について」（§7.1）。
- 著者の行は置かない（ログインしている本人なので）。

### 5.5 分割ビューとパネルの配置（オーナー決定 2026-11-05）

Cursor や Claude の分割ビューのように、パネルをある程度好きな場所へ動かせるようにする。ただし編集はメインだけで行い、置き場所の組み合わせは下の表に絞る（自由にしすぎると「どこへ行ったか」が分からなくなる）。モックは `docs/mockups/editor-split-view-v1.html`。

| パネル | 置ける場所 | 既定 |
| --- | --- | --- |
| ページ（編集する） | メイン（中央） | メイン |
| 右に並べたページ（読むだけ） | メインの右に 1 枚だけ | なし |
| 一覧（検索・新しいページ・木・このページの写真・設定の行） | 左のドック／右のドック | 左 |
| AIと作る | 左のドック／右のドック／メインの下に浮かせる | 右 |

- **右に並べる**：一覧の行を本文へドラッグすると「ここで開く」「右に並べる」の落とし先が出る。⌥クリック・行で ⌥Enter でも同じ（行の「…」には置かない。オーナー決定 2026-11-06）。右のページは読むだけで、書式の帯・保存の表示・公開はメインだけ。メインと同じページは右に置かない。
- **右のページの見た目**：題名は本文の先頭に 1 か所だけ置き、メインの題名と同じ大きさ・同じ高さにそろえる。上の帯は掴む所（⋮⋮）・入れ替え（⇄）・閉じる（×）だけで、「読むだけ」「入れ替える」の文字は出さない。
- **右のページを真ん中へ**：上の帯を掴んで真ん中へ落とすと、そのページがメインに入り、いまのメインは右へ移る（⇄ と同じ）。
- **URL**：`/p/{メイン}?side={右のページ}`。再読み込み・戻るで並びが残る。右の付け外しは履歴に積まない。
- **幅**：境目（一覧｜メイン｜右のページ｜右のドック）はドラッグで変えられる。フォーカスして ← →（Shift で大きく）、Home / End で最小・最大、ダブルクリックか Enter で既定の幅。最小はメイン 480px・右のページ 320px・ドック 240px。
- **入りきらないとき**：本人が決めた幅は覚えたまま、入らない間だけ「AI のないドックを細い列に畳む → 右のページを最小まで縮める → AI のドックを畳む」の順に詰める。細い列のアイコンを押すと上に重ねて開く（Esc で閉じる）。画面が広がれば戻る。
- **パネルを動かす**：一覧・AI の見出しを掴むと、近づけた場所に「落とすと入る形」を先に出す。左右の端ならそのドック、AI だけはメインの下端で浮かせる形。真ん中では何も起きない。同じドックに 2 つ入ったら一覧が上（高さの半分まで）・AI が下。見出しの「…」に「〜へ移す」の項目は置かない（ドラッグだけ。オーナー決定 2026-11-06）。
- **AI を浮かせる**：メインの下端に、本文と同じ幅（最大 680px）で浮かぶ。ふだんは入力欄 1 行で、送るか ⌃ で上へ広がり会話を出す。上端の取っ手で高さを変えられ、Esc で 1 行に戻る。本文の下には浮かべた高さぶんの余白を足し、書いている位置を隠さない。
- AI は置き場所を変えても、会話・書きかけ・実行中の依頼を失わない（作り直さずに同じ要素を付け替える）。AI の相手はどこに置いてもメインのページ。
- 配置と幅は端末ごとに覚える（ブラウザの保存領域。サーバーには置かない。画面の大きさが端末ごとに違うため）。
- 900px 未満は今のまま（§11）。分割・ドックの移動は出さず、覚えた配置も使わない。
- まだやらないこと：右のページの編集・タブ・2 枚目、上下の分割、右のページを AI の参考資料に足すこと（決定待ち）。

## 6. AI

- 「AIと作る」を常設する。既定は右のドックで、デスクトップでは既定で開く。左のドックへ移す・メインの下に浮かせることもできる（§5.5）。「整える・要約・見出しをつける・英語にする」などの定型ボタンは出さない。
- 見出しの右に鉛筆の「新しい会話」と三点の会話メニューを置く。会話メニューから履歴を読み、過去の会話へ切り替えられる。会話名や切り替え専用の行、別の履歴ボタンは増やさない。新しい会話を始めても元の履歴は残す。
- 入力欄は約 10 行まで自動で広がり、縦方向に手動でも広げられる。Enter で送信、Shift + Enter で改行し、日本語の変換確定では送信しない。「このページ」「Enter で送信…」「/ で工程・スキル」の補助文は置かない。
- 入力欄の「＋」と `/` は同じ工程・スキルの一覧を開く。工程は現在の録音・サブページの実際の手順を使い、実行できない段階は理由とともに無効にする。事実確認は指示文を入力欄へ入れ、送信は利用者が選ぶ。「ここまでを要約して軽くする」は会話の要約を作り、新しい会話に引き継ぐ。本文の要約を作る定型ボタンとは区別する。
- 固有名詞と誤りやすい表記は設定に持ち、AI が参照する。使用量は設定に出し、上限に近いときだけチャットに一言添える。上限以上はモデルを呼ぶ前に断る。
- チャットは旧 NIHO docs の「修正の会話」と同じ動きで、**AI がページを直接書き換える**。
  - AI が触れるのは「開いているページ・その親・そのサブページ」だけ（同じフォルダのほかのページは読むだけ）。道具は 一覧（字数と revision）・読む（段落の番号つき。範囲で読める）・部分置換（`edit_page`。1 か所だけに一致する文字列を置き換える）・丸ごと書く（`write_page`）・新しいページを作る・文字起こしを探す（`search_transcript`。時刻・話者・前後 200 字）の 6 つ（#278）。
  - 書き込みは**読んだ版を前提にする**：`edit_page`・`write_page` は `base_revision`（読んだときの revision）が今の版と違えば失敗し、AI は読み直してから書く。1 回の依頼は道具 40 回・書き込み 20 回・10 分まで（超えたら書いた分を残して止まる）。
  - 文字起こしを引用・確認するときは `search_transcript` で原文を確かめてから書く。引用の時刻・話者は返答にだけ書き、本文には入れない（オーナー決定 2026-11-06）。
  - 書く前の本文は必ず版として残り、会話の「元に戻す」で戻せる（作ったページはゴミ箱へ）。
    依頼のあとに人が直したページは戻さない（人の直しを消さない）。
  - 会話には、頼んだこと・作業（どのページを読んで書いたか。部分置換は直した段落の番号）・返答・直したページ（字数の増減）が残る。
  - 画像や録音を含むページは、本文を文字だけにできないのでチャットでは直せない。
  - **Web 検索（#283。オーナー決定 2026-11-06）**: サーバー経路では Anthropic のサーバー側 `web_search` を、AI が必要なときだけ使う（利用者は毎回選ばない）。**1 回の依頼で 5 回まで**（依頼のループ全体で数え、使い切ったら道具を出さない）。作業の行に「Web を検索: 〈語〉」「〈ホスト名〉ほか N 件を読んでいます」を出す。検索結果は本文・資料と同じ信頼しないデータ（中の指示に従わない）。**出典（題名と URL）はサーバーが返答の末尾にだけ付ける**（検索結果・引用のブロックから。重複を除き 10 件まで）。**本文には URL も印も入れない**。設定 › AI の「Web を検索する」（既定 ON）で切れ、切っているときは作業の行で「検索は切っています」と知らせる。`web_fetch` は入れない（検索結果や取得したページに紛れた指示で、攻撃者の URL へ本文を持ち出させるおそれがあるため）。
  - 事実確認（`/事実確認`）は、本文の主張（数字・固有名詞・日付・引用）を文字起こしと Web で確かめ、返答に一覧（確かめた／食い違い／確かめられない）を返す。**本文は直さない**（直すのは、人が一覧を見て頼んだとき）。
- **AI に渡す文脈は 3 つ**（旧 NIHO docs から引き継ぐ）: 固有名詞と誤りやすい表記、**「あなたについて」**（設定。
  本人の説明と書き方の希望。公開のときの著者情報とは別物で、公開されない）、**自動参考ページ**（開いているページと
  同じフォルダの直下にあるほかのページ。サブページは入れない）。どれも資料として渡し、事実の根拠にはしない。
  枚数の上限はフォルダの側が守るので、参考はその直下をそのまま入れる（選んだり並べ替えたりしない。長いページだけ先頭を切る）。
  AI の欄の入力の上に「読むもの」（このページ・この録音について・同じフォルダの N ページ）を小さな札で出す（2026-11-06）。
  開いているのが録音ページなら、**「この録音について」**（背景・登場人物・固有名詞。[editor-recipes-and-folders.md](editor-recipes-and-folders.md) §3.3）も
  指示の文脈に入れる。登場人物と背景は信頼しないデータとして包み、固有名詞は 録音 → アカウント共通 の順に並べる（2026-11-06）。
- **文を作る経路は 2 つ**。ブラウザ・PWA は**サーバーの API**（従量。月の上限で止まる）、Mac アプリは
  **この Mac の CLI**（利用者のサブスク。従量が出ないので**月の上限では止めない**）。どちらの経路でも、会話と結果は
  同じサーバーのページに載り、版と「元に戻す」も同じ。会話には**どの経路のどのエンジンが作ったか**を残す。
- 会話（AI チャット）はページごとに残る。ページを開くと最後の会話が出て、続けて頼める。鉛筆から新しい会話を始め、三点メニューから過去の会話へ戻る。
  鍵・プロンプト・モデルへ送った文は残さない。チャットが書き換えたものは、版から戻せる。
- 提案 → 採用の API（`/ai/proposals`・`/ai/adoptions`）は画面から呼ばれなくなったので外した（#278。オーナー決定 2026-11-06）。会話の表・列は残り、以前の提案の発言も履歴として読める。

### 6.1 実行経路は 2 つ（オーナー決定 2026-11-01：旧 NIHO docs の AI チャットを踏襲する）

| 面 | AI が動く場所 | 費用 |
| --- | --- | --- |
| ブラウザ・PWA（Mac で「サーバー AI」を選んだときも） | サーバー側の Anthropic API（Web 検索はサーバー側 `web_search`。1 依頼 5 回まで） | 使った分を `ai_usage` に数え、月の上限（USD）に入れる（Web 検索は 1 回ごとの従量も足す。上限の手前では検索を出さない） |
| デスクトップ（Mac アプリ） | **利用者の Mac で CLI を起動**（Claude Code・Codex CLI・Antigravity CLI。本人のサブスクのアカウント） | 従量の費用なし。**上限に数えない**（`ai_usage` には provider＝CLI・cost 0 で記録だけ残す） |

どちらの経路でも、**会話と結果は同じサーバーのページに載る**（会話の表とチャットの API は T5）。「接続中か」と「AI がどこで動くか」は別の軸で、Mac の CLI は接続中に動かして結果をサーバーへ書く。Mac でもサーバー側の API を選べる（設定）。

**CLI の往復（「文書ファイルは直接編集する」の形）。** 旧アプリでは CLI が手元の Markdown を直接書き換えていた。正本がサーバーになるので、**CLI が手元の作業コピーを直し、結果を同じ API でサーバーのページに書き戻す**：

1. 開始：Mac の bridge がサーバーから本文を読み、Markdown にして一時置き場（§13）の `page/body.md` に置く（限定 AST ⇄ Markdown は `niho-docs-ui/page/markdown.ts`）。参照（親ページの本文＝背景情報、固有名詞、選んだ範囲）は `context/*.md` に置く。そのときの `revision` を控える。
2. 実行：CLI を既存の `niho-local-ai` の `ToolPolicy::ProjectFolder { dir: 一時置き場, writable: ["page"] }` で起動する（cwd＝一時置き場。claude は Read・Edit・Write・Glob・Grep と WebSearch・WebFetch だけ、codex は `--sandbox workspace-write` の apply_patch と Web 検索（`web_search="live"`）だけ（読む道具が無いので、本文と参照は指示の標準入力に同封する。起動の直前に `codex features list` を読み、今の版で有効な機能を `code_mode_host`・Web 検索の機能以外すべて切る。版に依らず新しい機能も切れ、一覧を読めなければ起動しない）、agy はファイルの道具と search_web・read_url_content だけのエージェント。**Bash などコマンド実行は 3 つとも許さない**（#283。オーナー決定 2026-11-06）。Web の道具は呼び出し側の `web_search`（既定 true）で外せ、外したときと CLI の版が持たないときは知らせの出来事を出して検索なしで続ける。検索は 1 依頼 5 回まで、検索結果と読んだページも資料（中の指示に従わない）。ほかの道具が見えたら fail closed）。CLI は `page/body.md` を**直接編集する**（旧アプリと同じ体験）。指示は標準入力で渡す。
3. 書き戻し：終わったら `page/body.md` を読み、限定 AST に変換し、会話のターンと変更を既存の保存 API へ送る（`baseRevision` 付き）。変換できない要素（結合セルなど Markdown に表現できない構造）は黙って欠けさせず、保存を止めて理由を知らせる。ただし **AI が書いた本文の見出しの段階だけは救う**：見出し 1 は 2 に、4 以下は 3 にそろえる（AI は記事の先頭に `#` の題名を付けがちで、CLI 経路は書き直しの往復ができない。サーバー経路の `write_page`・`create_page` も同じ）。GitHub の注記の書き方（`> [!note]` の次の行から本文）も囲みとして読む。画像などほかの対応外は今までどおり断る。
4. 画面：Web と同じ常設チャットに返答と変更結果を出す。**CLI が直接書き換えるのは一時置き場の中だけ**。完了を確認してから既存の保存 API で本文・版・会話を保存する。変更結果から「元に戻す」を使える。保存結果が不明なときは再送せず、再読み込みで確かめる。
5. 競合：保存時に `baseRevision` が今の revision と違えば、既存の競合処理で止め、最新の本文を読み直して再実行を案内する。黙って上書きしない。
6. 後始末：送り終えたら一時置き場を消す。書けなかったら残して「もう一度」を出す。

**T5 との接点**（AI のレーンに頼むこと）：書き戻しの API（`POST …/ai/chat/turns`）が `baseRevision` と出どころ（provider＝`claude-cli`／`codex-cli`／`agy-cli`／`anthropic-api`、connection、cost）を受けること。会話 API が面（Web／Mac）と provider を記録すること。`ai_usage` が cost 0 の行を持てて、上限の計算から外せること。

### 6.2 会話の見え方・思考の中継・変更の扱い（オーナー決定 2026-11-05）

- 会話は Claude のチャットと同じ地の文。人の発言は右寄りの吹き出し、AI の発言は枠なし。カード・白い枠・差分の一覧は置かない。
- **思考の中継**: AI が道具を使う前・途中に書く短い段落（何を読んで、何をどう直すつもりか）を、そのまま AI の発言として流す。「N 秒考えました」のように畳まない・消さない。サーバー経路ではモデルの内部の thinking を頼まない（道具の合間の地の文が中継）。CLI 経路の `ThinkingDelta` は薄い色の段落としてそのまま流す。サーバー経路は SSE（`POST /api/pages/:id/ai/chat` に `Accept: text/event-stream`）で `text`／`tool`／`done` を流し、CLI 経路の `TextDelta`／`ThinkingDelta` も同じ描画に通す。
- 作業中は思考の下に薄い 1 行（「本文を読んでいます…」「第 3 段落を直しました」「文字起こしを『鎌倉』で探しています…」。サーバーが道具の中身から短い 1 句を作る。本文・プロンプトは入れない）だけ。送信ボタンは四角の「止める」に変わる。終わると消える。
- 作業中も入力欄は打てる。送ると**送信待ち**に積む（入力欄の上に「送信待ち N 件」。開くと中身が見え、1 件ずつ消せる。3 件まで。画面の中だけに持ち、サーバーにも localStorage にも置かない）。作業が**正常に終わる**と、1 秒おいて（その間は「取り消す」）先頭から順に送る。「止める」・失敗・取り消しのときは待ちを送らず、止めた依頼と待ちを順に入力欄へ戻す（言い直すかどうかは利用者が決める）。Mac の CLI 経路も同じ（CLI の結果を保存し終えてから次を起動する）。実行中の依頼に届く「割り込み」は作らない（編集前の版が残り、止めて言い直す損失が小さいため。#282）。
- **本文の選択範囲を渡す**（#280。NIHOapp の「選んで指示」）: 本文で範囲を選ぶと、入力欄の上に「選択範囲 N 字 ×」のチップが付き、本文の選択に薄い下地（`--ed-ink-mute` の薄め）が残る（入力欄へ移ってエディタの選択が消えても残る。選び直すと置き換わり、×で外すと普通の依頼）。⌘L（Ctrl+L）で入力欄へ移れる。送ると、依頼に **段落の番号（read_page の `n` と同じ最上位のブロックの 1 始まり）・字数・選んだ文字（先頭 2,000 字まで）・選んだときの本文の版** を添え、チップと下地は消える（結果に残らなかった依頼は、本文がそのままなら戻す）。送信中に選び直しても依頼の範囲は送ったときのまま。作業中と送信待ちがあるあいだは新しく選ばない。プロンプトには `<selection>` で包んで添え、system に「直してよいのはその範囲の中だけ」の決まりを足す。**守りはプロンプトだけにしない: 範囲の外の段落が 1 字でも変わる書き込み（`edit_page`・`write_page`・CLI の書き戻し）は、サーバーが版を残す前に断る**（範囲の中は段落が増減してよい。別のページへの書き込みも断る。`create_page` は新しいページなので許す）。選んだときの版と今の版が違えば 409（番号がずれるため）。Mac の CLI へは選んだ文字を `context/selection.md` に、「第 N 段落だけ直す・範囲の外は 1 字も変えない」を指示に添え、書き戻しにも同じ選択範囲を付けてサーバーが同じ検査をする。画像・録音ブロックの選択は扱わない（文字だけ）。
- **変更は即反映**（採用の段階は無い。書く前の版と「元に戻す」は今まで通り）。終わると「〈題名〉を直しました（−18 字）  変更を見る  元に戻す」の 1 行。
- **変更を見る**: 直す前の版（`change.version`）と今の本文の差分を本文に inline で描く（消した語＝取り消し線、足した語＝薄緑の下地＋下線、足したブロック＝左に緑の印）。表示中は読み取り専用で、本文の上に「AI の変更（版 N）を表示中 · 閉じる」。変更ごと（段落、または足したブロック）に「戻す」「これだけ残す」、帯に「すべて戻す」。戻す＝その段落を前の版の文に置き換える**普通の編集**（API は増やさない。保存と版は自動保存のもの）。AI のあとに人が編集していたら（今の revision が依頼の後の revision と違う）帯に一言添える。
- **AI が書いた印**: AI が足した語は mark `ai` 付きで保存され、灰色（`--ed-ink-mute`）で出る。人がその中に打った文字は黒（mark を外す）。⋯ の「AI の文を灰色で見せる」で切れる。公開・共有・Markdown・Google ドキュメントの出力では `ai` を落とす（公開契約には入れない）。
- **肉付け**: ＋ のスキル。本文の各段落を章の書き出しとして一字も変えずに残し、参照（録音の文字起こし・資料）から前後を補う。資料に無い事実は〔要確認: …〕。
- **実行先・モデル・思考量**（Mac。オーナー決定 2026-11-05）: 入力欄の下端の 1 行に「＋・今の実行先（`Claude Code · sonnet · 高 ▾`）・送信」を並べ、入力欄の上には選択欄を置かない。ボタンを押すと小さな窓が開き、実行先（3 つの CLI とサーバー AI。使えない CLI は理由つきで選べない）・モデル・思考量（既定・低・中・高・最大）を選ぶ。思考量はモデルに無い段階を選べない（docs-core の `effortRule`。Gemini 3.8 Flash は最大なし、思考量入りの名前のモデルは選ばない）。「既定」は `effort` を送らず CLI の設定のまま。選んだものは Mac ごとに localStorage へ覚える（CLI ごとのモデル・思考量）。サーバー AI の思考量は出さない（従量で月の上限に響くため。決めるまで固定）。Web（殻の外）は実行先がサーバー AI だけなので、このボタンを出さない。

## 7. 録音と手順

### 7.1 録音

- 「録音から」は録音ページを作り、録音ブロックが本文の上に入る（ブラウザのマイク、または音声ファイル・VTT の取り込み）。文字起こしはサーバー側のエンジン（設定で選ぶ）。Mac アプリの端末内エンジンは Web では使えない。
- **「この録音について」**（オーナー決定 2026-11-06。[editor-recipes-and-folders.md](editor-recipes-and-folders.md) §3.3）：録音ブロックの直下に 1 枚。話者人数・言語・登場人物・固有名詞・背景。録音ブロックがあるページにだけ出て、畳める。固有名詞は文字起こしのヒントに、三つとも手順の入力に入る。
- 文字起こしはページにしない。録音ページの本文で、見出し「文字起こし」の下に出る。文字起こしの前は「文字起こしを始める」だけが出て、手順の帯は押せない。
- 文字起こしは話者と時刻つきの段落。話者の名前は右下の一覧で変えられる（同じ話者をまとめることもできる）。時刻を押すとそこから再生。表示の切り替え（タイムスタンプ）。
- 文字起こしの段落はその場で直せる。直した内容は手順の入力になる。

### 7.2 手順

- AI の「記事にする」「議事録にする」は手順（テンプレート）を実行し、録音ページの下にサブページを作る。既定の手順は 4 つ（記事制作：文字起こし修正 › 記事方針 › 記事本文／議事録：議事録 › 共有用の要約／インサイト整理：インサイト／コーチング：文字起こし修正 › 分析）。
- 進み具合は各ページの上の帯に出る（済み・作成中・待機・失敗・前提変更）。サイドバーの行にも回るマーク。終わったら通知（ブラウザ通知は許可したときだけ）。
- サブページはふつうのページ。直すと、その先の手順は「前提変更」の印が付き、「作り直す」でその手順から再実行できる。印には変わった理由を 1 行添える（元の文字起こしが変わった、お手本が変わった、など）。
- 段階の出力が長くて途中で切れたら、続きを書かせて繋ぐ（旧 NIHO docs と同じ。続きは 8 回まで、重なりは 400 字まで除く）。終わらなければ失敗にして人に見せ、途中まで書けた文書はページに書かない（実装済み。#38）。
- 手順の中身（段階の名前、指示、お手本、段階ごとの重さ）は手順のページ（`/settings/recipes/{id}`。§2.2）で編集・追加・複製できる。段階は並べ替えられる。
- お手本は、文書ガイド（全段階に渡す書き方の指示）と、お手本の文書（ファイルと URL から取り込む）の 2 つ。お手本の文書から文書ガイドと固有名詞の候補を作る抽出は NIHO docs の工程設計を引き継ぐ。置き換える前に画面で確かめる。
- 段階ごとの重さは「標準・高性能・軽量」から選ぶ。モデルと鍵はサーバー側だけに置き、重さは思考量と出力の上限に訳す。長い文字起こしをほぼ同じ長さで書き直す段階は「軽量」でないと、思考が出力の上限を使い切って本文が出ない。
- 手順を直しても、始めた録音は作成時の写しのまま動く。「今の設計に更新」で何が変わるか（増えた・消えた・名前・指示・並び・お手本）を見せてから差し替える。
- 最後の段階（記事本文）はそのまま公開できる。題名は公開のシートで入れる（段階の名前のままでは公開できない）。手前の段階は自分だけのまま残る。
- 「画面を閉じても進む」実行基盤は editor 専用に決定し、実装済み（Cloud Tasks と OIDC で守った内部の route。[editor-steps-execution.md](editor-steps-execution.md)、#37）。手順の正本・設計の画面・旧 NIHO docs の工程設計からの引き継ぎは [editor-steps-recipes.md](editor-steps-recipes.md)。

## 8. 公開

### 8.1 公開のシート

1. **発信先**：writerが出せるNIHO Experience、接続した本人のサイト、「発信先を追加」。出せない発信先は理由を一言（接続する ›）。選ぶと下の項目がその発信先のものに変わる。
2. **記事の情報**（発信先を選ぶ前でも出る）：リード（160 字まで。残りは数字だけ）、カバー画像（本文の画像から選ぶ。無ければ選べない）、言語、英語版（状態と「英語案を作る」。決まりは ⓘ のシート）。
3. **範囲**：公開／限定公開（NIHO が運営する面だけ）。
4. **あわせて**：発信先が宣言した項目だけを出す。Experienceは「NIHOアプリに載せる」を著者が明示して選ぶ（既定OFF）。ニュースレターや体験ページ掲載の新機能は追加しない。
5. **公開の前に**：発信先の条件で足りないもの。「直す」でその欄へ（題名・本文はシートを閉じて本文へ、リード・カバー・言語・カテゴリ・関連はシートの中の欄へ）。全部そろうまで公開ボタンは押せない。
6. **URL**：`{host}/{path}/{slug}`。slug は題名から作り、初回の公開まで変えられる。公開後は固定。
7. ボタン：公開する／更新を公開／保存（設定だけ変えたとき）。公開中は「公開をやめる」。

発信先の条件（発信先が宣言し、editor は表示するだけ）：

| 発信先 | 条件 |
| --- | --- |
| NIHO Experience | 英語、カテゴリ、本文に見出し 1 つ以上、未確認の印（CONFIRM）なし、関連する体験が掲載中。カバー写真・リードは任意 |
| 本人のサイト | なし |

### 8.2 公開したあと

- 公開版は不変のスナップショット（本文 AST、Markdown、写真の参照、著者、カテゴリ、関連、公開日時）。直したら「更新あり」になり、「更新を公開」で入れ替わる。
- 「公開をやめる」は確認のうえで行い、ページは自分だけに戻る。発信先からは消え、URL は一覧へ転送（NIHO が運営する面）。再公開は同じ URL。
- 現行の運営記事公開先はExperienceだけ。Experience内のURL・公開停止後の動きはExperienceの契約に従う。本人のサイトから・へ移す場合の転送は約束しない（本人のサイトの作業）。
- 公開の予約は v1 では持たない。

### 8.3 発信先での見え方

「見る」は発信先が用意するプレビュー URL を開く。editor が短命のプレビュー用トークンを発行し、発信先はそのトークンで editor の API から下書きを読んで、自分の描画で `noindex` のページを返す。見え方の正本は常に発信先側にある。

## 9. 公開 API（契約）

- `GET /v1/{handle}/published.json`：公開中の一覧（id、slug、dest、lang、title、lead、cover、category、author、publishedAt、updatedAt、canonicalUrl、extras）。
- `GET /v1/{handle}/published/{id}.json`：公開版の本文（blocks、markdown、assets、related）。
- `GET /v1/preview/{token}.json`：プレビュー用。短命、本人の操作でだけ発行。
- 認証：本人のサイトは接続ごとの鍵（Bearer）。NIHO が運営する面はサービス間の認証。鍵は設定で再発行・失効できる。
- `ETag` と `If-None-Match`。一覧は更新順。公開をやめたものは一覧から消え、単体は 410。
- Webhook（公開・更新・停止の通知）は v1 では持たず、発信先は一覧を一定間隔で読む。必要になったら足す。
- 写真は editor の資産置き場から配信する URL。本人のサイトは取り込むときに複製する。
- 契約は `packages/`（公開）に置き、合成データの契約テストを持つ。認可の最終判断はサーバー側（[publication-gates.md](../security/publication-gates.md)）。

## 10. 役割と権限

- Editorはアカウント確認と公開操作のたびに、NIHOから現在writer許可を読む。役割をEditorへ複製しない。
- 出せる発信先：承認されたライター → NIHO Experience。本人のサイト → 解除していない本人接続があれば利用できる。
- 記事連携：招待・承諾・辞退・取消は NIHO の API。editor は「役割とつながり」で表示と承諾・辞退をするだけ。関連する体験の候補は、本人の体験と承諾済みの連携先の公開中の体験。
- 発信先の面は、公開版を受け取るときに自分で再確認する（体験が掲載中か、連携が有効か）。editor の表示を信用しない。

## 11. スマホとアクセシビリティ

- 900px 未満：サイドバーは一覧の画面、ページは全画面。AI は右のレール（全画面）で使い、画面下に別の AI の箱を出さない。公開は下からのシート。分割ビューとパネルの移動（§5.5）は出さない。
- 見出しの順番、ランドマーク、状態の読み上げ（保存・公開の状態は `aria-live`）。書式のバーとブロックの一覧はキーボードで操作できる。
- ショートカット：⌘N 新しいページ、⌘K 検索、⌘S 保存、⌘/ ブロックの一覧、⌘⇧P 公開のシート。
- 文字の最小は 12px。コントラストは NIHO の token に従う。

## 12. 失敗したときの扱い

| 場面 | 振る舞い |
| --- | --- |
| オフライン | 端末に保持し、戻ったら保存。右上に「オフライン・この端末に保持」 |
| 別の端末で保存された | 上に帯：「12:40 に別の画面で保存されました」。最新版を見る／本文をコピー／この内容で上書き。自分の文章は失わない |
| 書いている途中でログインが切れた | NIHOの更新cookieが有効なら画面の裏でsessionを更新し、同じページを開き直す。更新できなければ本文を端末に残し、ログイン後に同じページへ戻る |
| 公開に失敗した | 前の公開版はそのまま。下書きも残す。もう一度 |
| 文字起こしや手順が失敗した | 段階に「失敗」。もう一度／エンジンを変える。録音は消えない |
| 端末内の文字起こしの一時置き場が消えた・結果を書けない | 音声はサーバーの資産から取り直して文字起こしをやり直せる。結果をサーバーに書けなかったときは一時置き場を消さず、「もう一度」を出す（§13） |
| 削除 | ゴミ箱に 30 日。公開中のページを削除するときは先に公開をやめる |
| 音声の上限 | 1 ファイル 2 GiB・1 録音 6 時間まで。超えたら保存前に断る。クラウド音声は 30 日保持（オーナー決定 2026-11-01）。上限と保持日数は録音の断りと、設定の一覧の「データ」の ⓘ に出す（§2.2） |

## 13. リポジトリと配備

- `niho-docs` を `niho-editor` に改名。`apps/editor-web`（editor.niho.life）がこの設計の本体で、`packages/docs-ui`・`docs-core` の部品を使う。**ブラウザ・PWA・Mac アプリは同じ UI を同じサーバー相手に描く**（オーナー決定 2026-11-01：「editor.niho.life がメインで、それをデスクトップアプリが包み込む構成が基本」）。
- **Mac アプリ（`apps/docs`）は editor.niho.life を読む殻 ＋ 端末の力。** Tauri の webview が editor.niho.life をそのまま読む（UI を同梱しない。Web のデプロイで Mac も同時に更新され、dmg を出すのは native が変わるときだけ。オフラインは PWA のキャッシュと §12 の一時保持に任せる）。Mac だけの力は bridge（docs-ui の `DocsHost` の optional な native 操作）で UI に見せる：
  - マイクの録音（`niho-speech record`）
  - 端末内の文字起こし（同梱の `niho-speech` sidecar。音声と本文を**一時置き場**（app data）に置いて文字起こしし、**結果はサーバーの録音 API に書く**。§2.1）
  - CLI の AI（Claude Code・Codex・Antigravity CLI。本人のサブスクのアカウントで Mac で動かし、**提案はサーバーの同じ API に書く**。§6.1。「接続中か」と「AI がどこで動くか」は別の軸。これは「残す」ではなく**維持する機能**）
  - 音声ファイルの選択、鍵（Keychain）
  UI は capability を見て「この Mac で」の選択肢を出すだけで、画面は Web と同じ。
- 配布版は `NIHO_DOCS_SHELL` の値にかかわらず editor.niho.life を開く。`local` は開発・旧版検査だけ、`dev` は開発起動だけで localhost を開く。開発起動で未指定なら同梱画面を使う。
- **一時置き場は 1 つの仕組み**（端末内の文字起こしも CLI の AI も同じものを使う。2 つ作らない）：
  - 置き場は app data の `staging/<操作の id>/`（0700。`niho-local-ai` の `PrivateDir`・`scratch_dir` と同じ作法）。`~/Documents/NIHO docs` は使わない。
  - 中身：文字起こしは `audio/<file>`（この Mac で録った音声はそのまま、サーバーにある音声は取ってくる）と `context/background.md`。CLI の AI は `page/body.md`（書ける唯一の場所）・`context/*.md`・`instructions.md`（0600）。
  - 消し方：結果をサーバーに書けたら即消す。書けなかったら残して「もう一度」を出す。起動時に残骸を掃く（旧 `leftover_recordings` と同じ考え）。
  - 権限：CLI が書けるのは `page/` の下だけ（`ToolPolicy::ProjectFolder` の `writable`）。音声・context は読むだけ。
- **殻の安全性**（remote origin に IPC を開くので手を抜かない）：
  - Tauri v2 の capability で、IPC を許す origin を `https://editor.niho.life` だけに限る（`remote.urls`）。開発時の `localhost` は開発用の capability に分け、配布物には入れない。
  - 許す command を上の端末の力だけに絞る（録音・端末内の文字起こし・CLI の AI・ファイル選択・鍵）。旧い画面が使っていた保管庫の読み書き（`load_pages`・`write_page` など）は殻からは**呼べない**ようにする（退役とともに削る）。
  - **CLI の起動は特に厳しく。** remote から呼べるのは `ai_turn` のような**固定の形の command だけ**：`shell_ai_turn(turnId, { engine: "cli:claude-code" | "cli:codex" | "cli:antigravity", model, effort?, conversationId?, resumeSession?, instruction, page: { pageId, title, markdown }, context: [{ name, title, markdown }] })`（知らない項目は形ごと断る。`apps/docs/src-tauri/src/shell_ai.rs`）。パス・引数・環境・CLI の場所は**ページから受け取らない**。native の側で固定する：CLI のバイナリは今までどおり設定と環境変数（`NIHO_DOCS_*_CLI_PATH`・`cliPaths`）から決め、引数は `niho-local-ai` の固定の形、cwd は一時置き場、環境は crate の sanitize のまま。**指示の文は標準入力で渡す**（今までどおり）。
  - **シェルを通さない。** production の経路に `/bin/sh` は無い（`crates/local-ai/src/process.rs` の `/bin/sh` はテストの中だけ）。この不変条件を守り、「remote から来た文字列が `Command::new` の引数や `sh -c` に入らない」ことをテストで固定する。CLI の側の道具も Bash 等は許さない（`ToolPolicy::ProjectFolder` の fail closed のまま）。
  - CSP は Web 側（editor.niho.life の `Content-Security-Policy`）が正本。webview の側でも `connect-src` を editor.niho.life・`api.editor.niho.life`・**音声の送り先（`apps/editor-web/src/security/csp.ts` の `AUDIO_UPLOAD_ORIGIN` = `https://storage.googleapis.com`）** に限り、`script-src` に `unsafe-eval` を入れない。音声の取り込みと録音のアップロードは、画面（Web）がこの origin へ直接送るので、殻の側の追加の CSP は Web の応答の CSP では緩められない。2 つに絞ると音声が送れなくなる。送り先を替えるなら、先に別の経路（例：サーバー経由）を決めてから絞る。
  - 公開リポジトリなので、設定に書くのは実際のドメインだけ（内部の host・鍵・token は書かない。[publication-gates.md](../security/publication-gates.md)）。
- **旧 NIHO docs の画面は退役**：`DocsApp` 一式（レール・フォルダ画面・工程設計・AI と作る・設定）と、#109 で旗の裏に入れた `EditorScreen`・`vault-pages`・`vault-recordings`。残すのは native 層（`src-tauri` の録音・sidecar・AI の crate・鍵）と純粋ロジック（`docs-core` の工程・テンプレート・プロファイル・文字起こし。サーバーの手順の実装がこれを使う）。`desktop-vault`（三方向併合）と `DocsStorageMode` は退役。
- bundle identifier `life.niho.docs`・deep link `niho-docs`・配布物の名前 `NIHO-docs-<版>-<sha>`・tag `docs-v*` は変えない（#65）。
- 公開境界は [publication-gates.md](../security/publication-gates.md) のまま：クライアントと契約は公開、API・DB・鍵・認可は非公開。
- 認証は Editor アプリを入口にし、NIHO の公開確認画面 `/connect/niho-editor` から writer連携専用の `niho-experience-editor` client を使う（niho-app 側）。Experience は連携先として編集権限だけを判定する。Mac の殻も `editor.niho.life` の同じ origin を読む。
- CI は標準の GitHub-hosted runner。secret なし。

| 段階 | 内容 | 使えるようになること |
