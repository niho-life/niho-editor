# Mac の Gemini CLI 文字起こし

対象は Mac アプリから共通の録音画面を開いた場合。通常のブラウザから別の Mac へ処理を依頼する機能は含めない。調査・比較候補は [実装案](../../idea/active/2026-11-03-mac-gemini-cli-transcription.md) を参照する。

## 分割と実行元

Gemini の分割目標はオーナー指定の **600 秒（10 分）**。近くの無音へ境界を調整する。端末内認識の900秒は変更しない。10分は捏造が起きないことを保証する長さではない。

既存の `Provider::GeminiCli`（Antigravity CLI / `agy`）を使い、`gemini-3.8-flash` / `low` / 音声だけを読む `ReadFile` に固定する。音声は Google 側へ送られる。API キー方式へ自動で切り替えない。

## 処理の境界

1. 共通の録音画面が、認証済み本人の録音に結び付く Mac 実行を開始する。サーバーは実行ID、世代、固定設定、音声一覧を返す。
2. 画面が同一originの音声routeから最大4MiBずつ取得し、native stagingへ渡す。nativeにURL・資格情報・任意パス・CLI引数・環境変数は渡さない。
3. nativeが長さとSHA-256を照合し、変換・分割する。サーバーの音声番号に欠番があっても、nativeのファイル番号は一覧順に揃え、元のoffsetを保持する。
4. 未完了区間をCLIで処理し、既存docs-coreの指示・解析・時刻補正・話者の整列で結合する。短すぎる出力と出力上限は最大3回再試行し、利用制限・認証エラーは繰り返さない。
5. 完了区間と結合結果をprivate app dataに保持してから、画面がサーバーへ結果を確定する。保存成功後に一時データを破棄する。

画面は `apps/editor-web`、native呼び出しは `packages/desktop-bridge`、音声処理はMacの殻に置く。`packages/docs-ui` にTauri依存を追加せず、旧Project/vaultの保存経路を復活させない。

## 保存と再開

既存の `transcription_runs` と録音候補を使う。サーバー実行とMac CLI実行をexecutorで区別し、Mac実行をCloud Tasksのclaim・再投入・時間切れ・失敗処理に混ぜない。

結果受付は本人・ページ・実行・世代・operation・音声集合を確認する。録音・ページのlock後に音声を照合し、停止後や古い世代、別ページ、削除済みページの結果を確定しない。同じ開始・完了の再送で重複反映しない。

結果は「文字起こし」ページの新しいタブ（#310。札「Gemini（このMacのCLI）」）に書く。開始でタブを作り、run の書き先（`target_tab`）にする。実行中に編集されたタブは上書きせず、競合した生成結果はMacに保存待ちで残して知らせる。

停止・CLI制限・失敗後は、音声と設定が同じ場合だけ未完了区間から再開する。保存通信だけ失敗した場合はCLIを起動せず結果だけを再送する。保存済み応答の取りこぼしも成功として復元する。checkpointは世代とrevisionのCASで古い書き手による上書きを拒否する。

ページ移動時に実行を止め、古い画面のcallbackを無効化する。再起動後の復元は本人のサーバー実行を取得して照合する。閉じたままの常駐実行は含めない。通常ブラウザ・旧Macアプリには入口を出さない。

## 検証と制約

対象テストで10分の引数、複数音声offset、参考文・話者、出力不足、停止、保存再送、破損checkpoint、native排他とID制限、APIの権限・世代・削除・音声変更・重複受付を検証する。DBテストは合成データと専用schemaを使う。

2026-11-03の実CLIテストは短い日本語の合成音声を既存ReadFile adapterへ渡したが、`UsageLimitReached` で停止した。実CLIの完走と長時間音声の忠実度は未確認。10分から5分への自動再分割は今回含めない。
